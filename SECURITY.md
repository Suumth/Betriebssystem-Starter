# Security Policy

This starter is a public template. It should not contain private project data, local machine paths or credentials.

## Reporting

Use GitHub Security Advisories for sensitive reports when available.

If advisories are not available in your fork or copied project, open a minimal private report through your normal repository maintainer channel.

## Scope

Relevant reports include:

- accidental credential material
- unsafe default permissions
- workflow behavior that writes when it should be read-only
- template content that could expose private project data
- documentation that encourages unsafe release, merge or access behavior

## Handling

Security-related changes should use a focused Pull Request with clear evidence and a Review of Record.

Do not publish sensitive details in a public Issue before a maintainer has reviewed the report.
